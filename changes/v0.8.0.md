# v0.8.0

## Breaking

- `esquadro gen` refuses to run with a release of esquadro newer than the
  one that last generated the project: run `esquadro upgrade`, which shows
  these notes and then generates. One older than the project's refuses too.
- The spa's words: `src/messages.ts` now holds only the words you change and
  your own; the frontend's are in `src/esquadro/kit/messages.ts`
  (generated). If you never changed yours, `esquadro upgrade` replaces it;
  if you did, keep only your changes in it, in the new shape.
- The spa's menu: `src/menu.ts` starts from `src/esquadro/menu.gen.ts`
  (generated) instead of listing every entry.
- The spa's sign-in and account pages (login, forgot and reset password,
  confirm email, forbidden, settings) come from `src/esquadro/kit/pages/`;
  `src/pages/...` only shows them.
- Deleting a record of an entity with `@store(soft_delete)` puts it in the
  trash; `DELETE /<plural>/trash/{id}` deletes it for good.

## New

- A `.once` file you never changed follows its template; one you changed
  gets the template's changes merged in, as `git merge` does, from the base
  kept in `esquadro/base/` (commit it). Conflicts are marked; `gen` stops
  until they are resolved.
- A conflict of a merge is marked with the lines as they were too
  (`||||||| base`), as git's `diff3` style. `esquadro gen -dry-run -json`
  describes what a generation would do, for editors; the VS Code
  extension shows it in a panel and opens conflicts in the merge
  editor.
- Blueprints `seed`, `audit` and `notifications`; the trash
  (`@store(soft_delete)`); service keys, accounts, the history of a record,
  the audit and the notifications in the spa; rich text (`@rest(html)`),
  many-to-many links written with the record (`tag_ids`), date and time
  pickers; signing in with Google and GitHub in the spa.

## How to migrate

1. Install this esquadro, then in the project: `esquadro upgrade -dry-run`,
   read what would change, and `esquadro upgrade`.
2. Commit `esquadro/base/` with the rest of `esquadro/`.
   A project from v0.7.0 has no base yet: a `.once` file you changed is kept
   as it is this time (`keep` in the list), and compare it with the
   template by hand if you want what is new in it (`esquadro explain
   <file>` names the template); from the next upgrade on, it is merged.
3. Resolve any conflict `esquadro upgrade` lists (between `<<<<<<< yours`
   and `>>>>>>> esquadro`), then `esquadro gen -check`.
