# v0.16.0

## Added

- River's own screen of the job queue, served by the API behind sign-in:
  `blueprint jobs { ui "/jobs" }`. It lists the jobs by state, with their
  errors and attempts, and retries, cancels and deletes them. Only the
  roles `ui_access` names may open it (`[user.admin]`; by default, those
  who administer the first realm's accounts). Someone not signed in gets a
  page asking them to sign in first; someone without the role gets a 403.
  The screen needs the security blueprint with a principal, and
  `esquadro check` says so.
- `security.EmbeddedUI`, for a screen of a library the app embeds: it
  checks the session and the roles. A request that changes something
  under the screen's path must come from the API's own address, because
  such pages send no CSRF token. The rest of the API still asks for the
  token. Each such request is logged with who made it.
- Alerts for each app of the platform, from Grafana:
  - a job that failed, was given up, keeps retrying, or, on a schedule,
    is late;
  - an integration that fails its check;
  - 5xx answers and slow answers;
  - an app that keeps restarting;
  - a database not backed up.

  They go to the owner by email and, with `alerts_telegram_token` and
  `alerts_telegram_chat_id` in the platform's secrets, on Telegram. They
  come in English or Portuguese (`alerts_language`), with limits of their
  own (`alerts_http_error_ratio`, `alerts_http_p95_seconds`,
  `alerts_restarts`, `alerts_backup_hours`).
- A Grafana dashboard for each app, at `/d/app-<name>`: requests, 5xx,
  latency, jobs, the queue, integrations, the database's connections,
  memory and the error logs.
- With observability, the jobs blueprint measures the queue: `jobs.queue`
  (by kind and state), `jobs.discarded`, and `jobs.periodic.overdue` for a
  job on a schedule that has not worked in time. The last success and
  error of each such job are kept in `jobs_periodic_runs`, because River
  deletes completed jobs after a day.
- `blueprint integration <name> { check true }`: the worker checks the API
  when it starts and every hour, logs a failure and records
  `integration.check`.
- The backup command tells Grafana of each database it backed up
  (`platform.backup.last_success`).

## Changed

- Each process sends its own `service.instance.id`. Before, the API and the
  worker of an app sent their metrics under the same labels, so one
  overwrote the other.
- An integration's key and secret lose the spaces and line breaks at their
  ends.
- River is now v0.51.2, with riverui v0.23.0. The upgrade has no new
  migration of River's own; `esquadro gen` raises the version in go.mod.
