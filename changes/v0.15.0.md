# v0.15.0

## Added

- The session says what the person may do with each resource of the API,
  before any list is asked: `access`, in the answer of sign-in and of
  `GET session`, from the model's rules. For each entity and report: the
  operations (`list`, `read`, `create`, `update`, `delete`, `import`,
  `restore`, `purge`, the steps of flows), those only on records of one's
  own (`own`), and the fields left out (`hidden`). A frontend hides what
  would be refused; the API still decides each request.
- The same `access` says who administers a realm's accounts:
  `accounts/user` (`list`, `create`, `update`, `delete`), for a team page
  shown only to them.
