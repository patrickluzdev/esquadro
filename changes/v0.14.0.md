# v0.14.0

## Added

- `styles css` on an ssr site: its styles are plain CSS (`site.css`, yours),
  which the app's binary serves as written, after the theme's tokens
  (`theme.gen.css`). No Node, Tailwind, htmx or `package.json`, and no
  blueprint workspace: the Dockerfile, the CI and the Taskfile build no
  frontend for it. For a link shortener or a small site. `site.css` comes
  with a rule for every class of the pages esquadro writes; a class your
  pages add is yours to write there. `styles tailwind`, the default, is the
  site as before.

## Changed

- The ssr blueprint no longer requires workspace: a site with
  `styles tailwind` still needs it, and `esquadro gen` says so.
- `internal/platform/web/frontend.go` comes from the ui blueprint, which
  every frontend uses, instead of workspace.

## Upgrading

- A site that should not build with Node: write `styles css` in its
  blueprint, and `esquadro gen`. An untouched `site.css` follows; one you
  changed keeps its Tailwind, and is yours to write in plain CSS. Delete
  the site's `package.json` (and `esquadro/base/web/<site>/package.json.base`)
  yourself: esquadro leaves a file it wrote once to you. Delete
  `node_modules/` and `package-lock.json` when no other frontend uses them.
